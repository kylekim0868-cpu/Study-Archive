## 딕셔너리를 재귀 호출마다 초기화함

### 당시 코드

```python
def fibonacci_memo(n, memo=None):
    memo = {}
```

### 문제점

재귀 호출마다 새로운 빈 딕셔너리가 만들어진다. 부모 호출이 넘긴 `memo`를 자식 호출이 이어서 사용할 수 없으므로 이전 계산 결과가 유지되지 않는다.

### 수정한 이해

`memo`가 전달되지 않은 최초 호출에서만 딕셔너리를 만든다.

```python
if memo is None:
    memo = {}
```

`if memo:`는 비어 있지 않은 딕셔너리에서 참이 되므로 이 목적에 맞지 않는다. 여기서는 값이 없는 상태인 `None`을 정확히 확인한다.

## 저장만 하면 중복 계산이 사라진다고 생각함

### 당시 생각

```text
n = 5 → memo에는 {5: f(4, memo) + f(3, memo)}
n = 4 → memo에는 {5: ..., 4: f(3, memo) + f(2, memo)}
```

계산식이 먼저 딕셔너리에 들어가므로 같은 함수 호출이 중복되지 않는다고 생각했다.

### 원인

대입문의 실행 순서를 계산식 저장처럼 이해했다. Python은 오른쪽 식을 먼저 전부 계산한 후 그 결과값을 왼쪽에 대입한다.

```python
memo[5] = fibonacci_memo(3, memo) + fibonacci_memo(4, memo)
```

위 코드는 `{5: f(3) + f(4)}`를 미리 저장하지 않는다. 두 함수의 반환값을 구하고 더한 뒤 최종 숫자를 `memo[5]`에 저장한다.

### 수정한 이해

저장과 재사용은 별개의 작업이다. 저장된 key가 있는지 직접 검사하고, 있으면 저장된 value를 반환해야 중복 계산을 막을 수 있다.

```python
if n in memo:
    return memo[n]
```

## `return n`과 `return memo[n]`을 혼동함

### 당시 코드

```python
if n in memo:
    return n
```

### 문제점

`n`은 구하려는 피보나치 수의 인덱스다. 재사용하려는 계산 결과는 딕셔너리의 value인 `memo[n]`이다.

예를 들어 `n = 3`, `memo = {3: 2}`일 때 `return n`은 `3`을 반환하지만 필요한 값은 `2`다.

### 수정

```python
if n in memo:
    return memo[n]
```

## 딕셔너리에 값을 추가하는 방법을 혼동함

### 발생했던 오류

```text
AttributeError: 'dict' object has no attribute 'append'
```

### 원인

`memo`는 리스트가 아니라 딕셔너리다. 리스트의 `append()` 방식으로 값을 넣을 수 없다.

### 수정한 이해

하나의 key와 value를 저장할 때는 key를 지정해 대입한다.

```python
memo[n] = 계산한_결과
```

## 기저 조건의 결과도 memo에 저장된다고 생각함

`fibonacci_memo(5)`를 추적하면서 최초 저장값을 `memo[0]`이라고 생각했다.

현재 코드는 `n == 0` 또는 `n == 1`이면 즉시 `return`한다. 따라서 아래의 `memo[n] = ...`에 도달하지 않으며 `0`과 `1`은 딕셔너리에 저장되지 않는다. 가장 먼저 저장되는 항목은 `memo[2] = 1`이다.
