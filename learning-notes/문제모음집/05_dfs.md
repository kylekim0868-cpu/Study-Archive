## `None`에 `append()`를 호출함

### 오류 메시지

```text
AttributeError: 'NoneType' object has no attribute 'append'
```

처음에는 그래프 크기만큼 방문 배열을 생성해야 한다고 생각했다.

```python
if not visited:
    for i in graph:
        visited.append([None])
```

하지만 최초 호출에서 `visited`는 `None`이다. 아직 리스트가 만들어지지 않았는데 `append()`부터 호출했기 때문에 오류가 발생했다. 빈 딕셔너리에 키를 만들지 않고 `append()`했던 그래프 문제와 비슷했다. 데이터를 추가하려면 데이터를 담아줄 자료구조부터 먼저 만들어야 한다.

또한 `visited`는 그래프 크기만큼 미리 공간을 만드는 배열이 아니었다. 실제로 방문한 정점을 순서대로 추가하는 리스트다.

```text
최초 상태 → []
0 방문    → [0]
1 방문    → [0, 1]
```

## 빈 리스트의 마지막 위치에 값을 대입하려고 함

```python
visited[-1] = start
```

`visited`를 빈 리스트로 만든 직후에는 `-1` 위치도 존재하지 않는다. 기존 위치의 값을 바꾸는 것이 아니라 현재 방문한 정점을 새롭게 기록해야 하므로 `append()`의 역할이 필요했다.

## 현재 정점이 아닌 1번 정점만 확인함

### 당시 코드

```python
for i in range(len(graph)):
    if graph[1][i] not in visited:
```

DFS는 재귀 호출마다 현재 정점이 달라진다. 그런데 `graph[1]`로 고정하면 어디에서 재귀 호출됐든 항상 1번 정점의 이웃만 확인한다.

또한 `len(graph)`은 전체 정점 수지만 `graph[1]`은 1번 정점의 이웃 목록이다. 두 길이가 항상 같지 않으므로 존재하지 않는 인덱스에 접근할 수도 있다.

현재 필요한 것은 그래프 전체의 인덱스가 아니라 `graph[start]`에 들어 있는 이웃 정점 자체였다.

## 방문 처리의 역할을 두 곳에 둘 뻔함

처음에는 이웃을 발견한 쪽에서 `visited`에 추가하고 재귀 함수를 호출하려고 했다. 하지만 각 DFS 함수가 시작될 때 자신의 `start`를 방문 처리한다면 호출하는 쪽에서는 방문 여부만 확인하면 된다.

```text
현재 DFS 함수 → 자신의 start를 방문 처리
반복문        → neigh의 방문 여부 확인
재귀 호출     → 미방문 neigh를 다음 start로 전달
```

방문 처리를 양쪽에서 모두 담당하면 같은 정점을 중복으로 기록할 수 있다. 하나의 동작을 어디에서 책임질지 먼저 정해야겠다.

## 다시 확인할 질문

- `visited`는 미리 크기를 정하는 배열인가, 방문할 때마다 늘어나는 기록인가?
- `graph`를 순회할 때와 `graph[start]`를 순회할 때 각각 어떤 값이 나오는가?
- 현재 함수가 방문 처리를 담당한다면 호출하는 쪽에서는 무엇만 확인하면 되는가?
- 더 이상 방문하지 않은 이웃이 없을 때 재귀 함수는 어디로 돌아가는가?
