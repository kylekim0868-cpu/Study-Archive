# Algorithm — 이진 트리와 재귀 순회

## 한 문장 정의

이진 트리는 노드 하나가 최대 두 개의 자식을 가질 수 있는 자료구조다. 재귀 순회에서는 현재 노드를 루트로 하는 서브트리의 방문 결과를 만들고, 그 결과를 이전 호출에 반환한다.

## 노드의 구조

처음에는 노드 하나가 `int` 자료형이라고 생각했다. 예제에서 `value`가 정수라서 노드 자체와 노드가 가진 값을 섞어서 생각한 것이었다.

```text
노드
├─ value → 현재 노드가 가진 값
├─ left  → 왼쪽 자식 노드
└─ right → 오른쪽 자식 노드
```

`left`와 `right`에는 단순한 값이 아니라 다른 노드를 가리키는 정보가 들어 있다. 자식 노드가 없다면 `None`을 가리킨다.

## 이진 트리와 이진 검색 트리의 차이

처음에는 이진 검색 트리가 완전 이진 트리여야 한다고 생각했다. 하지만 완전 이진 트리인지 여부는 BST가 되기 위한 필수 조건이 아니었다.

```text
이진 트리
→ 노드 하나가 최대 두 개의 자식을 가짐
→ 값의 크기에 대한 규칙은 없음

이진 검색 트리
→ 현재 노드보다 작은 값은 왼쪽
→ 현재 노드보다 큰 값은 오른쪽
```

한쪽으로 치우친 트리도 값의 규칙을 만족한다면 이진 검색 트리가 될 수 있다.

## 재귀 함수가 해결하는 작은 문제

처음에는 왼쪽과 오른쪽 자식의 반환값이 빌 때까지 재귀를 진행한다고 생각했다. 하지만 재귀의 종료 기준은 반환값이 비었는지가 아니라 현재 노드가 `None`인지 여부다.

재귀 함수 하나가 해결하는 작은 문제는 다음과 같다.

> 현재 노드를 루트로 하는 서브트리를 정해진 순서로 순회하고, 그 방문 결과를 리스트로 반환한다.

예를 들어 현재 노드가 2이고 자식이 4와 5라면, `preorder(2)`는 2를 루트로 하는 작은 트리의 전위 순회 결과 `[2, 4, 5]`를 만들어 이전 호출에 반환한다.

## Base Case에서 빈 리스트를 반환하는 이유

현재 노드가 `None`이면 그 방향에는 방문할 노드가 없으므로 탐색을 종료한다. 현재 구현은 하위 함수가 반환한 리스트들을 연결하여 결과를 만들기 때문에, 노드가 없을 때도 같은 자료형인 빈 리스트를 반환해야 한다.

```text
[현재 노드] + [] + []
→ 리스트끼리 연결할 수 있음

[현재 노드] + None + None
→ 리스트와 None은 연결할 수 없음
```

Base Case는 단순히 재귀를 멈추는 역할만 하는 것이 아니라, 상위 호출에서 사용할 수 있는 형태의 값을 반환해야 한다.

## `append()`와 리스트 연결의 차이

```text
append(value)
→ 기존 리스트의 마지막에 값 하나를 추가
→ 반환값은 None

list_a + list_b
→ 두 리스트의 원소를 연결
→ 새로운 리스트를 반환
```

리스트 자체를 `append()`하면 리스트의 원소들이 합쳐지는 것이 아니라, 리스트 하나가 원소로 들어가 중첩 리스트가 된다.

```text
[1]에 [2, 3]을 append
→ [1, [2, 3]]

[1]과 [2, 3]을 연결
→ [1, 2, 3]
```

또한 현재 노드를 `append()`한 뒤 `result`에 새로운 리스트를 다시 할당하면 앞에서 추가한 값이 사라질 수 있다. 한 줄을 실행한 뒤 변수에 무엇이 남는지 추적해야 한다.

## 전위·중위·후위 순회의 차이

처음에는 순회마다 시작 노드가 바뀐다고 생각했다. 하지만 같은 루트에서 시작하며, 달라지는 것은 현재 노드를 결과에 기록하는 위치다.

```text
전위 순회 → 현재 + 왼쪽 + 오른쪽
중위 순회 → 왼쪽 + 현재 + 오른쪽
후위 순회 → 왼쪽 + 오른쪽 + 현재
```

- 전위 순회는 왼쪽과 오른쪽을 탐색하기 전에 현재 노드를 기록한다.
- 중위 순회는 왼쪽 탐색이 끝난 뒤 현재 노드를 기록한다.
- 후위 순회는 왼쪽과 오른쪽 탐색이 모두 끝난 뒤 현재 노드를 기록한다.

왼쪽과 오른쪽 탐색 순서를 바꾼다고 결과 전체가 반드시 역순이 되는 것은 아니다. 현재 노드를 기록하는 위치는 그대로이고, 두 서브트리의 탐색 순서만 바뀐다.

## 호출 스택이 기억하는 것

처음에는 호출 스택이 현재 위치한 노드만 기억한다고 생각했다. 호출 스택은 현재 노드뿐만 아니라 함수의 실행 상태와 재귀 호출이 끝난 뒤 이어서 실행할 위치를 함께 기억한다.

```text
호출 스택
→ 어떤 함수가 실행 중이었는가?
→ 현재 처리하던 노드는 무엇인가?
→ 자식 호출이 끝난 뒤 어느 줄부터 이어갈 것인가?
```

왼쪽 재귀 호출이 끝나면 무조건 가운데나 오른쪽으로 이동하는 것이 아니다. 왼쪽 재귀를 호출했던 코드의 바로 다음 실행 지점으로 돌아간다.

## 복잡도

모든 노드를 한 번씩 방문하므로 순회 자체의 시간복잡도는 `O(n)`이다. 하지만 현재 구현처럼 각 재귀 호출에서 리스트를 연결해 새로운 리스트를 만들면 리스트를 복사하는 비용이 추가된다.

- 균형 잡힌 트리: 리스트 연결 비용까지 고려하면 대략 `O(n log n)`
- 한쪽으로 치우친 트리: 리스트 연결 비용까지 고려하면 최악의 경우 `O(n²)`
- 재귀 호출 스택 공간: 트리의 높이 `h`만큼 사용하므로 `O(h)`

호출 스택의 깊이는 전체 노드 수보다 트리의 높이에 따라 달라진다.

```text
균형 잡힌 트리 → 높이 O(log n)
치우친 트리   → 높이 O(n)
```
