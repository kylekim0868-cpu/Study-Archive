# DP 피보나치 — 설계 기록

- 풀이 코드: [`06_dp_fibonacci.py`](../../week3/1.%20basic/06_dp_fibonacci.py)
- 문제점 기록: [DP 피보나치 — 문제점 기록](../문제모음집/06_dp_fibonacci.md)
- 진행 상태: 메모이제이션 핵심 구조 작성, 실행 검증 전

## 처음 세운 나만의 설계

1. 기준값을 `n = 1 → 1`, `n = 0 → 0`으로 정한다.
2. `fib(5) → fib(4) + fib(3)`으로 작은 문제를 재귀 호출한다.
3. `fib(4) → fib(3) + fib(2)`에서 `fib(3)`이 두 번 등장하는 것을 발견한다.
4. `n`을 key로 두고 `fibonacci_memo(n-2, memo) + fibonacci_memo(n-1, memo)`를 value로 넣는 방법을 생각한다.
5. 이 설계가 기존 일반 재귀와 무엇이 다른지 의문을 가진다.

## 최초에 생각한 memo의 모습

```text
n = 5 → {5: f(4, memo) + f(3, memo)}
n = 4 → {5: ..., 4: f(3, memo) + f(2, memo)}
```

이 설계에는 중복되는 부분 문제를 발견하고 딕셔너리에 기록하려는 DP 방향의 사고가 들어 있었다. 다만 계산식이 먼저 저장된다고 생각했고, 저장한 결과를 다시 찾는 단계가 빠져 있었다.

## 디버깅하며 바뀐 사고

### 1. 하나의 memo를 공유해야 한다

매 호출에서 `memo = {}`로 초기화하면 기록이 사라진다. 최초 호출에서만 딕셔너리를 만들고 재귀 호출에는 같은 객체를 전달한다.

### 2. 계산식이 아니라 결과값이 저장된다

Python은 대입문의 오른쪽을 먼저 계산한다. `memo[n]`에는 재귀식 자체가 아니라 계산이 끝난 숫자가 들어간다.

### 3. 저장과 조회를 모두 해야 한다

결과를 저장해도 조회하지 않으면 재귀 함수는 같은 부분 문제를 다시 계산한다. 재귀 호출 전에 `n in memo`를 검사하고, 있으면 `memo[n]`을 즉시 반환한다.

### 4. 일반 재귀와 Top-down DP의 경계

```text
일반 재귀: 같은 부분 문제를 만나도 다시 계산한다.
Top-down DP: 같은 부분 문제를 만나면 저장한 결과를 반환한다.
```

`f(n-2) + f(n-1)`로 분해하는 것까지는 둘이 같다. 계산 결과를 저장하고 재사용하는 단계가 추가되어야 메모이제이션을 사용한 Top-down DP가 된다.

## 현재 설계

1. `memo`가 `None`인 최초 호출에서 빈 딕셔너리를 만든다.
2. `n`이 기저 조건이면 값을 즉시 반환한다.
3. `n`이 `memo`에 있으면 저장된 `memo[n]`을 반환한다.
4. 없다면 두 부분 문제를 재귀 호출한다.
5. 계산 결과를 `memo[n]`에 저장한다.
6. 저장한 결과를 반환한다.

## `fibonacci_memo(5)` 손 추적

현재 코드가 `n-2`를 먼저 호출하므로 저장 순서는 다음과 같다.

```text
memo[2] = 1
memo[3] = 2
memo[4] = 3
memo[5] = 5
```

최종 key-value 대응은 다음과 같다.

```python
{2: 1, 3: 2, 4: 3, 5: 5}
```

`{5: 5, 4: 3, 3: 2, 2: 1}`도 key-value 대응 자체는 같지만, 현재 실행에서 딕셔너리에 추가되는 순서를 표현한 것은 아니다.
