# BFS — 설계 기록

- 풀이 코드: [`04_bfs.py`](../../week3/1.%20basic/04_bfs.py)
- 문제점 기록: [BFS — 문제점 기록](../문제모음집/04_bfs.md)
- 진행 상태: 제공된 테스트 통과

## 문제를 읽고 정한 역할

```text
graph   → 정점별 이웃 목록
start   → 탐색을 시작하는 정점
queue   → 앞으로 이웃을 조사할 정점의 대기 줄
visited → 이미 발견한 정점의 기록이자 최종 방문 순서
current → 이번 반복에서 큐에서 꺼낸 정점
neigh   → current와 직접 연결된 이웃 정점
```

## 손으로 추적한 예제

```python
graph = {
    0: [1, 2],
    1: [0, 2],
    2: [0, 1, 3],
    3: [2],
}
```

시작점 `0`에서의 상태 변화:

```text
시작
queue = [0]
visited = [0]

0을 꺼냄
0의 이웃 1, 2를 발견
queue = [1, 2]
visited = [0, 1, 2]

1을 꺼냄
0, 2는 이미 발견됨
queue = [2]
visited = [0, 1, 2]

2를 꺼냄
3을 새로 발견
queue = [3]
visited = [0, 1, 2, 3]

3을 꺼냄
2는 이미 발견됨
queue = []
```

큐가 비면 더 조사할 정점이 없으므로 탐색을 끝낸다.

## 자연어 설계에서 코드로 옮긴 과정

```text
시작점을 대기 줄과 방문 기록에 넣는다
→ queue = deque([start])
→ visited = [start]

대기 줄에 정점이 남아 있는 동안 반복한다
→ while queue:

대기 줄의 첫 정점을 꺼낸다
→ current = queue.popleft()

현재 정점의 모든 이웃을 확인한다
→ for neigh in graph[current]:

처음 발견한 이웃만 기록하고 대기 줄에 넣는다
→ if neigh not in visited:
→ visited.append(neigh)
→ queue.append(neigh)
```

## 이웃 선택 순서에 대한 이해

시작점 `0`의 이웃 `1`, `2`는 모두 거리가 1이다. 문제에 작은 번호부터 방문하라는 조건이 없다면 둘 중 누가 먼저 큐에 들어가도 BFS다.

```text
graph[0] = [1, 2] → 방문 순서: 0, 1, 2, ...
graph[0] = [2, 1] → 방문 순서: 0, 2, 1, ...
```

BFS가 보장하는 것은 같은 거리 안의 세부 순서가 아니라, 가까운 거리의 정점들을 먼저 처리한다는 점이다.

## 다음 복습 때 확인할 핵심

- 큐를 비우는 것이 아니라, 한 정점을 꺼낸 뒤 새 이웃을 큐 뒤에 추가한다.
- 새 이웃은 큐에 넣는 순간 방문 처리한다.
- 무방향 그래프에서는 `visited`가 없으면 정점들이 서로를 계속 큐에 추가해 탐색이 끝나지 않을 수 있다.
